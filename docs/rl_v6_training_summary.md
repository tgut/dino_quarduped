# RL v6 训练总结报告

> 日期：2026-04-08 | 仿真引擎：PyBullet | 算法：PPO (Stable-Baselines3)

## 一、版本演进

| 版本 | 表现 | 核心问题 |
|------|------|----------|
| v1 | 双腿蹦跳 | 步态理解错误 |
| v2 | 趴在地上不动 | reward hacking（趴着不会扣分） |
| v3/v4 | 冲刺后摔倒 | 速度奖励过大导致激进 |
| v5 | 站着不走 | alive bonus(3.0) 压制速度奖励(1.5)，走vs站仅差1.4% |
| **v6** | **稳定行走** | 重新平衡奖励，走vs站差15% |

## 二、v6 核心改进

### 奖励函数调整
- 速度奖励权重翻倍：1.5 → **3.0**，sigma 收紧 0.25 → **0.15**
- 存活奖励降低：3.0 → **2.0**，不再"站着躺赢"
- 惩罚项全面减半（平滑性 -0.03→-0.015、能耗 -0.003→-0.0015、姿态正则 -0.02→-0.01）

### PPO 超参数
- 网络架构：3层 MLP (256→128→64)，policy / value 共享结构
- n_steps：2048 → **4096**（更稳定的梯度估计）
- batch_size：64 → **128**
- entropy coefficient：0.01 → **0.005**（减少随机探索）
- 其他：lr=3e-4, gamma=0.99, gae_lambda=0.95, clip=0.2, epochs=10
- 并行环境：8 个 SubprocVecEnv

### 环境配置
- 观测空间：41维（高度、姿态、速度、关节角/角速度、相位时钟、接触信息）
- 动作空间：12维（4腿×3关节目标角度）
- 控制频率：60Hz（physics 240Hz, action_repeat=4）
- 最大步数：1000 steps/episode
- 训练总步数：2,030,000（约2M）

## 三、奖励函数详细设计

### 正向奖励（always ≥ 0）
| 项目 | 权重 | 公式/说明 |
|------|------|----------|
| 速度跟踪 | 3.0 | `3.0 * exp(-((vx - 0.20)² / 0.15))` |
| 存活奖励 | 2.0 | 每步固定 +2.0 |
| 高度跟踪 | 1.0 | 目标 0.155m |
| 姿态跟踪 | 0.5 | roll/pitch 越小越好 |
| 足底接触 | 0.15/足 | 0~0.6（0-4 只脚着地） |
| 相位步态 | 0.5 max | 对角步态（trot）相位匹配 |
| 前后对称 | 0.3 max | 前后腿同步接触奖励 |

### 惩罚项
| 项目 | 权重 | 说明 |
|------|------|------|
| 身体接触 | -0.5 | 非足底部位触地 |
| 垂直速度 | -2.0 | 抗弹跳，cap at vz²≤1.0 |
| 横向速度 | -0.15 | 防侧滑 |
| 偏航角速度 | -0.05 | 防原地打转 |
| 动作平滑性 | -0.015 | 相邻帧动作差的平方和 |
| 能耗 | -0.0015 | 关节力矩平方和 |
| 关节速度 | -0.0005 | 关节角速度平方和 |
| 默认姿态正则 | -0.01 | 偏离默认站姿的偏差 |
| 死亡惩罚 | -20.0 | 仅在 termination 时 |

### 奖励估算对比
- 站着不动：~6.1/step
- 前进行走：~6.8/step（+15%）
- 随机动作：~2.4/step（正值，不会"死得快"）
- 早死@8步：8×2.4 - 20 = -0.8（不划算）

## 六、已知问题：腿部抖动

视频中可观察到行走时腿部有明显抖动，分析原因：

1. **控制频率偏低 (60Hz)**：physics 240Hz / action_repeat=4，关节间步进间隔大
2. **动作平滑性惩罚过轻 (-0.015)**：v6 为"鼓励探索"减半了平滑惩罚
3. **前进速度波动大**：策略未学到稳定步态模式
4. **接触数偏低 (0.586)**：平均不到 0.6 只脚着地，支撑相偏短
5. **身体高度偏低 (0.122 vs 目标0.155m)**：半蹲姿态下小幅动作被放大

## 七、v7 优化方向

- [ ] 加大 action smoothness 惩罚：-0.015 → -0.04
- [ ] 引入关节加速度惩罚项
- [ ] 增大 foot contact 奖励，鼓励更长支撑相
- [ ] 提高控制频率：action_repeat 4→2（60Hz→120Hz）
- [ ] 延长训练到 5M 步（reward 曲线尾部仍在缓慢上升）
- [ ] 考虑 curriculum learning，从慢速走逐步提速
