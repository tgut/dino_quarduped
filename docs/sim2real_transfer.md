# 恐龙四足机器人 - Sim2Real Transfer 指南

## 什么是 Sim2Real Transfer

Sim2Real Transfer（仿真到真实迁移）是指将 PyBullet 仿真中训练/调好的控制策略，
部署到真实物理机器人上并保持正常工作的过程。

核心挑战：**Reality Gap（现实差距）**——仿真中完美行走的策略直接部署到实机往往失败。

---

## Reality Gap 的来源

| 仿真假设 | 真实情况 | 影响 |
|----------|---------|------|
| 舵机瞬间到达目标角度 | DS3218 响应延迟 ~0.15s/60° | 动作滞后，步态失调 |
| 关节无间隙 | 3D 打印件装配间隙、齿轮回差 | 位置精度下降 |
| 地面完美平坦 | 地面不平、摩擦系数不均 | 滑动、绊倒 |
| 传感器无噪声 | MPU6050 有漂移和噪声 | 状态估计不准 |
| 质量/惯量精确 | 实际重量分布与 URDF 有偏差 | 重心偏移、动力学不匹配 |
| 控制频率稳定 50Hz | 树莓派 I2C 通信有抖动 | 控制周期不均匀 |
| 碰撞为刚体 | 脚垫有弹性、关节有柔性 | 接触力学不同 |

---

## 三层解决方案

### 第一层：Domain Randomization（仿真端）

在 PyBullet 训练时故意加入随机扰动，让策略"见过各种糟糕情况"，
到实机上就不容易崩。

#### 需要随机化的参数

```python
# 在 rl/dino_env.py 的 reset() 中加入随机化
randomization_ranges = {
    # 动力学参数
    "body_mass":       (1.2, 1.8),    # kg, 标称 1.5 ±20%
    "friction":        (0.4, 1.0),    # 地面摩擦系数
    "joint_damping":   (0.01, 0.1),   # 关节阻尼
    "joint_friction":  (0.0, 0.05),   # 关节摩擦

    # 执行器特性
    "action_delay":    (1, 3),        # 控制步延迟 (模拟舵机响应)
    "action_noise":    (0.0, 0.02),   # 动作噪声 (rad)
    "torque_scale":    (0.8, 1.2),    # 扭矩缩放

    # 传感器噪声
    "imu_accel_noise": (0.0, 0.5),    # m/s² 加速度噪声
    "imu_gyro_noise":  (0.0, 0.05),   # rad/s 角速度噪声
    "imu_gyro_drift":  (0.0, 0.01),   # rad/s 陀螺仪漂移

    # 环境
    "ground_slope":    (-5, 5),       # 度, 地面倾斜
    "push_force":      (0, 3),        # N, 随机侧向推力
}
```

#### 随机化策略

- **均匀随机化**：每次 reset() 时从范围内均匀采样
- **渐进式**：训练前期不加或少加随机化，后期逐渐增大范围
- **相关性**：某些参数可以关联随机化（如质量增大时惯量也增大）

### 第二层：System Identification（实机端）

用实际硬件数据修正仿真模型，缩小仿真与现实的差距。

#### 2.1 质量/惯量标定

```
操作步骤：
1. 电子秤称量每个零件实际重量
2. 更新 urdf/dino.urdf 中的 mass 和 inertia
3. 安装完成后称量整机重量
4. 用吊线法测量实际重心位置

需要记录：
  部件              设计值(g)   实测值(g)
  ────────────────────────────────────
  机身框架          120         ?
  树莓派 3B          45         ?
  PCA9685           15         ?
  电池              280         ?
  单个 DS3218        60         ?
  ...
  总重              1500         ?
```

#### 2.2 舵机响应曲线

```python
# 在实机上测量舵机实际响应特性
# 发送阶跃信号，记录到达时间

# 测量项：
# - 空载响应时间：0° → 60° 需要多少 ms
# - 负载响应时间：带负载（腿重量）的响应时间
# - 回差测量：正转到 90° 再反转回来，偏差多少度
# - 实际角度精度：命令 45° 实际到达多少度

# 用这些数据更新仿真中的关节参数：
# - maxVelocity
# - jointDamping
# - lateralFriction
```

#### 2.3 IMU 噪声特性

```bash
# 静止状态采集 60 秒数据
python3 hardware/04_imu_test.py > imu_static_60s.csv

# 分析：
# - 加速度计零偏 (bias)
# - 加速度计噪声方差 (noise)
# - 陀螺仪零偏和漂移率
# - Allan 方差（可选，更精确）
```

#### 2.4 地面摩擦测量

```
简易方法：
1. 将机器人脚垫放在目标地面上
2. 逐渐倾斜，记录开始滑动的角度 θ
3. 摩擦系数 μ = tan(θ)
4. 更新 PyBullet 中的 lateralFriction 参数
```

### 第三层：渐进式部署（实机端）

不直接跑完整策略，分步验证，逐步提高复杂度。

```
Step 1: 站立
  └─ 验证 IK 角度映射正确
  └─ 脚本: hardware/05_stand_test.py
  └─ 通过标准: 四脚着地、机身水平、高度 ~150mm

Step 2: 单腿抬放
  └─ 固定三条腿站立，一条腿做抬起/放下动作
  └─ 验证单腿轨迹跟踪精度
  └─ 确认舵机响应速度够用

Step 3: 慢速 Trot
  └─ 脚本: hardware/06_trot_test.py --slow
  └─ 步幅减半、周期加倍
  └─ 确认基础步态可行

Step 4: 正常速度 Trot（固定步态）
  └─ 脚本: hardware/06_trot_test.py
  └─ 确认动态稳定性

Step 5: 部署 RL 策略（v7 PPO 模型）
  └─ 用 RL 模型输出替代固定步态生成器
  └─ 树莓派上用 ONNX Runtime 推理
  └─ 50Hz 控制循环: IMU 读取 → 模型推理 → 舵机输出
```

### 模型导出

```python
# 训练完成后，将 PPO 模型导出为 ONNX
import torch

model = PPO.load("rl/checkpoints/v7_best.zip")
policy = model.policy

dummy_obs = torch.randn(1, obs_dim)
torch.onnx.export(
    policy,
    dummy_obs,
    "rl/checkpoints/v7_policy.onnx",
    input_names=["observation"],
    output_names=["action"],
    opset_version=11,
)
```

### 实机推理

```python
# 树莓派上用 ONNX Runtime 推理
import onnxruntime as ort

session = ort.InferenceSession("v7_policy.onnx")

while running:
    obs = get_observation()  # IMU + 关节角度
    action = session.run(None, {"observation": obs})[0]
    action = np.clip(action, -action_limit, action_limit)
    send_to_servos(action)
    time.sleep(0.02)  # 50Hz
```

## 评估指标

部署后需要对比仿真和实机的性能差异：

| 指标 | 仿真值 (v7) | 实机目标 | 测量方法 |
|------|-------------|---------|---------|
| 站立稳定性 | CoM 偏移 <2mm | <5mm | IMU 积分 |
| 行走速度 | ~0.15 m/s | >0.10 m/s | 秒表 + 距离 |
| Roll/Pitch 幅度 | <5° | <10° | IMU 数据 |
| 续航时间 | N/A | >60 min | 实测 |
| 抗扰能力 | 侧推 3N | 侧推 2N | 手动推测 |
